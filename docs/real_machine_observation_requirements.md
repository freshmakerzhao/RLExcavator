# 真机部署观测信息需求说明


## 1. 策略做什么


接收：

- 当前铲斗位置和速度
- 当前执行器状态
- 未来若干个轨迹点
- 当前任务模式
- 当前铲斗姿态

它输出 4 维连续动作：

| 动作 | 含义 | 当前仿真控制对象 | 真机部署含义 |
|---|---|---|---|
| `boom` | 大臂动作 | 大臂液压缸目标速度 | 大臂液压缸速度或等价控制命令 |
| `stick` | 小臂动作 | 小臂液压缸目标速度 | 小臂液压缸速度或等价控制命令 |
| `bucket` | 铲斗动作 | 铲斗液压缸目标速度 | 铲斗液压缸速度或等价控制命令 |
| `swing` | 上车回转 | 回转铰链目标角速度 | 回转速度或等价控制命令 |

当前策略关注两类任务：

| 模式 | 名称 | 目标 |
|---|---|---|
| `MoveToDig` | 移动到挖掘点 | 铲斗接近入铲/垂直姿态，同时跟踪轨迹 |
| `CarryMaterial` | 带土运输 | 铲斗接近水平或略后仰姿态，同时跟踪轨迹 |

---

## 2. 当前策略观测向量

当前 ML-Agents `Vector Observation Space Size = 37`。

| 序号 | 观测内容 | 维度 | 真机是否需要 | 来源建议 |
|---|---:|---:|---|---|
| 1 | 铲斗尖在车体坐标系下的位置 | 3 | 必须 | 关节编码器 + 正运动学，或外部定位/视觉估计 |
| 2 | 铲斗尖在车体坐标系下的速度 | 3 | 必须 | 铲斗位置差分，或 FK + 关节速度 |
| 3 | 大臂/小臂/铲斗/回转执行器归一化位置 | 4 | 必须 | 液压缸位移传感器、关节编码器，或等价状态估计 |
| 4 | 大臂/小臂/铲斗/回转执行器归一化速度 | 4 | 必须 | 液压缸速度、关节角速度，或位置差分 |
| 5 | 上一步策略动作 | 4 | 软件内部可得 | 控制程序缓存上一帧输出 |
| 6 | 未来 3 个 waypoint 相对铲斗尖的位置误差 | 9 | 必须 | 上层规划器给轨迹点，低层根据当前铲斗位置计算 |
| 7 | 当前轨迹完成进度 | 1 | 软件内部可得 | waypoint index / waypoint count |
| 8 | 当前目标是否为最后一个 waypoint | 1 | 软件内部可得 | 轨迹管理器计算 |
| 9 | 铲斗到当前轨迹段 tube 的 signed distance | 1 | 软件内部可得 | 根据轨迹点和当前铲斗位置计算 |
| 10 | 当前控制段进度 | 1 | 软件内部可得 | 低层控制器计时或步数归一化 |
| 11 | 任务模式 one-hot | 2 | 必须由任务层提供 | 上层任务规划器提供 `MoveToDig` 或 `CarryMaterial` |
| 12 | 当前铲斗 pitch | 1 | 必须 | 铲斗姿态估计、FK、IMU，或二者融合 |
| 13 | 目标铲斗 pitch | 1 | 软件内部可得 | 由任务模式查表得到 |
| 14 | 铲斗 pitch 误差 | 1 | 软件内部可得 | 当前 pitch 与目标 pitch 做角度差 |
| 15 | 铲斗 pitch 角速度 | 1 | 必须/建议 | IMU、关节速度 + FK，或 pitch 差分 |

## 3. 真机必须提供的数据

如果只看部署推理，真机侧最少需要提供以下信息。

### 3.1 执行器状态

必须提供四个执行器的当前位置和速度：

| 状态 | 推荐单位 | 当前仿真对应 |
|---|---|---|
| 大臂液压缸位置 | m 或归一化值 | `BoomNormalizedPosition` |
| 小臂液压缸位置 | m 或归一化值 | `StickNormalizedPosition` |
| 铲斗液压缸位置 | m 或归一化值 | `BucketNormalizedPosition` |
| 回转角度 | rad 或归一化值 | `SwingNormalizedPosition` |
| 大臂液压缸速度 | m/s 或归一化速度 | `m_jointVelocity.x` |
| 小臂液压缸速度 | m/s 或归一化速度 | `m_jointVelocity.y` |
| 铲斗液压缸速度 | m/s 或归一化速度 | `m_jointVelocity.z` |
| 回转角速度 | rad/s 或归一化速度 | `m_jointVelocity.w` |

注意：

- 仿真中前三个动作控制的是液压缸伸缩速度，不是直接控制关节角。
- 真机如果能直接拿到液压缸位移/速度，和当前仿真接口最接近。
- 如果只能拿到关节角/角速度，也可以使用，但需要重新统一归一化和运动学模型。

### 3.2 铲斗尖位置和速度

必须实时估计铲斗尖在车体坐标系下的位置：

```text
p_bucket_tip_base = [x, y, z]
v_bucket_tip_base = [vx, vy, vz]
```

推荐来源：

1. 液压缸位移/关节角 + 挖掘机几何参数做正运动学。
2. 铲斗或连杆 IMU + 编码器融合。
3. 外部视觉/定位作为校验，不建议作为唯一来源。

坐标系建议：

- 使用车体上车坐标系或挖掘机根坐标系。
- 训练和部署必须一致。
- 当前仿真里使用的是 `agent.transform` 局部坐标系。

### 3.3 铲斗姿态

两种任务模式都需要当前铲斗 pitch：

```text
bucket_pitch_deg
bucket_pitch_velocity
```

推荐来源：

1. 铲斗连杆正运动学计算。
2. 铲斗 IMU 直接估计 pitch。
3. FK + IMU 融合，提高抗噪声能力。

需要提前标定：

- 哪个姿态叫“铲斗垂直入铲”。
- 哪个姿态叫“铲斗水平运输”。
- 当前策略中的 `bucketPitchFrame`、`bucketPitchAxisLocal`、`moveToDigTargetBucketPitchDeg`、`carryMaterialTargetBucketPitchDeg` 必须与真机定义一致。
- `bucketPitchFrame` 应对应随上车回转一起旋转的上车/驾驶室/回转平台坐标系；否则 swing 会错误影响 bucket pitch。

### 3.4 轨迹点

低层策略不自己规划任务，它需要上层给定未来轨迹点。

至少需要：

```text
waypoint_0_base = [x0, y0, z0]
waypoint_1_base = [x1, y1, z1]
waypoint_2_base = [x2, y2, z2]
```

如果上层只给完整轨迹，低层轨迹管理器需要维护当前 waypoint index，并提取未来 3 个点。

轨迹点坐标系必须和铲斗尖位置一致。

### 3.5 任务模式

上层任务系统需要告诉低层当前处于哪种模式：

| 模式 | 编码 |
|---|---|
| `MoveToDig` | `[1, 0]` |
| `CarryMaterial` | `[0, 1]` |

这个模式不是传感器直接测得，而是任务规划器/状态机给出的命令。

## 4. 软件内部可以计算的数据

以下数据不需要传感器直接提供，但真机部署程序必须能计算。

| 数据 | 计算方式 |
|---|---|
| 上一步动作 | 控制器缓存上一帧策略输出 |
| waypoint 相对误差 | `waypoint_position - bucket_tip_position` |
| 路径完成进度 | 当前 waypoint index / waypoint 总数 |
| 是否最后 waypoint | 当前 index 是否为最后一个 |
| tube signed distance | 铲斗尖到当前轨迹段线段的距离与 tube 半径比较 |
| episode / 控制段进度 | 当前控制步数 / 最大控制步数 |
| 目标 bucket pitch | 根据任务模式查表 |
| bucket pitch error | 当前 pitch 与目标 pitch 的角度差 |

## 5. 仿真训练/评估专用数据

以下信息可以用于训练奖励、评估或日志，但不应该作为当前低层策略的真机推理输入。

| 数据 | 用途 | 真机是否必须 |
|---|---|---|
| AGX 接触信息 | 判断入土、碰撞、材料交互 | 非当前轨迹策略必须 |
| bucket payload | 带土任务奖励、洒落评估 | 当前可选，后续挖装任务重要 |
| 土方体积变化 | 挖掘任务效果评估 | 当前可选 |
| 是否撒料 | CarryMaterial 奖励/评估 | 后续建议估计，但不一定作为策略输入 |
| 成功/失败标志 | TensorBoard 统计 | 软件内部计算 |
| waypoint reach rate | 策略评价 | 软件内部计算 |
| cumulative reward | 训练诊断 | 真机不需要 |

原则：

> 真机推理输入只能依赖真机可稳定获得的数据；AGX 特权信息最多用于仿真训练奖励、自动标注或离线评估。

## 6. 推荐的真机数据接口

建议真机状态估计模块每个控制周期输出如下结构。

```text
timestamp

base_frame:
  name

actuators:
  boom_position
  stick_position
  bucket_position
  swing_position
  boom_velocity
  stick_velocity
  bucket_velocity
  swing_velocity

bucket:
  tip_position_base: [x, y, z]
  tip_velocity_base: [vx, vy, vz]
  pitch_deg
  pitch_velocity_deg_s

trajectory:
  waypoints_base:
    - [x0, y0, z0]
    - [x1, y1, z1]
    - [x2, y2, z2]
  current_waypoint_index
  waypoint_count

task:
  mode: MoveToDig | CarryMaterial
```

控制器输出：

```text
commands:
  boom_normalized_speed:   [-1, 1]
  stick_normalized_speed:  [-1, 1]
  bucket_normalized_speed: [-1, 1]
  swing_normalized_speed:  [-1, 1]
```

底层执行器再把归一化速度映射到真实液压缸速度、阀控命令或电机命令。

## 7. 频率和延迟建议

当前仿真中通过 ML-Agents `DecisionRequester` 周期性决策，物理层会在两个决策之间保持动作。

真机建议：

| 项目 | 建议 |
|---|---|
| 状态估计频率 | 不低于 20 Hz，优先 50 Hz |
| 策略推理频率 | 10-20 Hz 起步，后续按真机稳定性调整 |
| 底层执行器控制频率 | 高于策略频率，由底层控制器插值/保持 |
| 时间戳 | 必须有，用于差分速度和延迟补偿 |
| 延迟 | 尽量稳定；比低延迟更重要的是延迟可估计 |

如果状态延迟较大，建议在部署侧加入：

- 速度滤波
- 时间同步
- 状态预测
- 动作限幅和加速度限制

## 8. 标定检查清单

给真机传感器/状态估计同学的最小检查项：

- 能否实时获得大臂、小臂、铲斗液压缸位置？
- 能否实时获得大臂、小臂、铲斗液压缸速度？
- 能否获得上车回转角度和角速度？
- 能否根据传感器状态稳定计算铲斗尖在车体坐标系下的位置？
- 能否计算铲斗尖速度？速度噪声是否可接受？
- 能否估计铲斗 pitch？
- 能否估计铲斗 pitch 角速度？
- 能否统一车体坐标系、轨迹点坐标系、铲斗位姿坐标系？
- 能否给每帧状态打时间戳？
- 能否保证推理时不会使用仿真中特权信息？

---

## 9. 当前最需要先验证的真机能力

优先级从高到低：

1. 铲斗尖位置 FK 是否准确。
2. 铲斗 pitch 定义是否稳定、可重复。
3. 液压缸位置/速度和仿真中的归一化定义能否对齐。
4. 轨迹点能否转换到同一个车体坐标系。
5. 控制命令是否能稳定映射到液压缸速度或等价执行器命令。

如果前 3 项无法稳定获得，当前策略不适合直接部署，需要先做真机状态估计或重新设计观测空间。

---

## 10. 与后续研究的关系

当前文档只覆盖“低层轨迹跟踪策略”的真机观测需求。

它不覆盖：

- 从土堆感知中自动生成 dig point。
- 从场景图中预测挖掘意图。
- bucket payload 的真机估计。
- 土方变化和装车完成度估计。
- 完整无人挖装任务状态机。

这些可以作为上层感知、规划和任务管理模块继续扩展。低层策略只要求上层给出可跟踪的轨迹点和任务模式。
